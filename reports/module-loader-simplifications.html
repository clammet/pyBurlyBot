Module loader simplifications

Implemented. Plugins now use a package namespace, bare names, explicit shared state, and per-server activation.

Changes

StatusChangeResult
Done Package-based imports pyburlybot_modules/ is a real package. Plugins load as pyburlybot_modules.<name> through normal importlib.import_module() calls. The entry point no longer adds the plugin directory to sys.path.
Done Removed the pbm_ convention Filenames, configuration names, dependencies, option namespaces, and module lookup calls now use bare names such as random and users. Package qualification prevents collisions with top-level Python modules.
Done One explicit registry ModuleRegistry owns imports, import failures, per-server active modules, activation failures, unloads, and cache cleanup.
Done Per-server activation Imported Python modules remain shared, while availability is tracked separately for each server. A plugin loaded by one server can no longer appear available to another.
Done Simple loading pipeline Dispatcher now performs named stages: import, requirements, options, initialization, add-ons, and activation. Each stage has one error boundary.
Done Consistent requirement handling Requirements normalize to a tuple and checking always returns the same (not_allowed, failed) shape. Disallowed requirements are reported without being imported, and circular errors include the dependency path.
Done Metadata defaults Missing REQUIRES, OPTIONS, PROVIDES, and mappings values use empty defaults instead of repeated presence checks.
Done Central reload lifecycle The registry unloads active plugins once, removes package children from sys.modules, invalidates import caches, reloads all servers, and reports failures. Direct stale-module cleanup was removed from settings.
Done One mapping sort pass All event and command buckets are built first, then each bucket is sorted once.

Verification

  • Bundled random, time, and wikipedia plugins import without replacing their top-level dependencies.
  • The multiprocessing class from pyburlybot_modules.logindexsearch serializes with its package-qualified import name.
  • Tests cover denied dependencies, string requirements, circular dependencies, pipeline stages, per-server isolation, source reloads, and mapping order.

This intentionally changes configuration compatibility: existing pbm_ names should be replaced with bare plugin names.
